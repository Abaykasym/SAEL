# Перенос SAEL на Hosting.kg с Plesk

Версия 2.1 включает админ-панель, помощника с базой знаний и чат сотрудников. Подключение ИИ и операторской — ASSISTANT_GUIDE.md. Инструкция первого входа — ADMIN_GUIDE.md. При обновлении существующей установки сохраняйте .env и data/: архив содержит код, но не содержит пароли и сохранённые материалы.

## 1. Проверить Node.js и сохранить старый сайт

В Plesk откройте «Сайты и домены» → нужный домен → Node.js. В некоторых версиях пункт находится в «Создать сайт». Нужна поддерживаемая LTS-версия Node.js; рекомендуем 24 и менеджер npm. Наличие Plesk само по себе не означает, что Node.js доступен в тарифе.

Если пункта нет, отправьте в поддержку Hosting.kg этот текст самостоятельно:

> Нужно разместить Node.js-приложение SAEL в Plesk: Node.js 24 LTS, npm, точка запуска server.js, отдельные Application Root и Document Root (public). Доступен ли Node.js Toolkit на нашем тарифе? Разрешён ли исходящий SMTP с TLS на порт 587/465? При переносе sael.kg необходимо сохранить существующий кабинет /cb и /cb/pricelist.pdf. Просим уточнить, как оставить их за прежним приложением. Для ограничения заявок по IP требуется достоверный X-Real-IP: заменяет ли его ваш прокси и какие адреса непосредственного прокси следует доверять?

До переключения основного сайта создайте резервную копию файлов, баз данных и настроек старого сайта средствами Plesk. Сохраните копию также вне этого хостинга.

## 2. Сначала использовать тестовый поддомен

Создайте, например, new.sael.kg в «Сайты и домены» → «Добавить поддомен». Основной sael.kg и кабинет пока продолжают работать на старой конфигурации. Включите SSL-сертификат и перенаправление HTTP на HTTPS.

Тестовый поддомен закройте от индексации на уровне хостинга (X-Robots-Tag: noindex) или ограничьте доступ средствами Plesk. Этот запрет необходимо снять при публикации основного сайта. Рабочие HTML-файлы не содержат noindex.

## 3. Загрузить архив

Откройте «Файлы», загрузите sael-site-cms-ai-plesk.zip и распакуйте в отдельную папку sael-site вне публичного корня старого сайта. Сохраните структуру:

```text
sael-site/                 Application Root
  server.js
  cms-server.js
  cms-setup.js
  cms-seed.json
  package.json
  package-lock.json
  .env.example
  README.md
  DEPLOY_PLESK.md
  RELEASE_CHECK.md
  ADMIN_GUIDE.md
  data/                    создаётся при работе; хранить вне public и не стирать при обновлении
  public/                  Document Root
    index.html
    about.html
    service.html
    app.js
    ...css и остальные публичные js
    assets/
    admin/
      index.html
      admin.css
      admin.js
```

Если распаковщик создаст дополнительную папку, выбирайте корень, в котором непосредственно находится server.js. Удалите загруженный ZIP из доступного через браузер каталога. Не загружайте node_modules с Windows и не назначайте всю папку приложения публичным корнем.

## 4. Настроить приложение

| Параметр | Значение |
|---|---|
| Node.js Version | 24 LTS, если доступна у провайдера |
| Package Manager | npm |
| Application Mode | Production |
| Application Root | папка sael-site с server.js |
| Document Root | public внутри этой папки |
| Application Startup File | server.js |

Полный путь зависит от подписки и показывается в Plesk. Выберите «Включить Node.js», затем «NPM Install», после настройки — «Restart App / Перезапустить приложение». Отдельно запускать npm start в фоне через панель не нужно: приложением управляет Plesk.

Если Plesk обслуживает CSS/JS/картинки напрямую через nginx/Apache, заголовки Node.js на эти ответы не распространяются. HTTPS, сжатие и защитные заголовки следует проверить на публичном адресе и при необходимости задать через администратора хостинга. HSTS включайте после проверки HTTPS на нужных доменах.

## 5. Подключить отправку КП

Задайте закрытые переменные Plesk или создайте .env **рядом с server.js, вне public** по .env.example:

```dotenv
SMTP_HOST=сервер_вашей_почты
SMTP_PORT=587
SMTP_SECURE=false
SMTP_USER=логин_почтового_ящика
SMTP_PASS=пароль_или_пароль_приложения
SAEL_FROM=подтверждённый_адрес_отправителя
SAEL_QUOTE_TO=sael.karabalta@saelglobal.com
```

Для порта 465 установите SMTP_PORT=465 и SMTP_SECURE=true. Для 587 используется обязательный STARTTLS. Параметры берите у администратора почты: они не определяются по адресу получателя. Не отключайте проверку TLS. Не публикуйте .env и скриншоты паролей. На хостинге не задавайте PORT=8020, если провайдер управляет портом приложения.

TRUST_PROXY_IPS по умолчанию пустой. Заполняйте только адресами непосредственного прокси, подтверждёнными хостингом, при гарантированном замещении X-Real-IP. Не включайте доверие всем адресам.

Перезапустите приложение. Затем самостоятельно отправьте тестовые заявки с отдельной тестовой почты: без файла, с PDF, с DOCX/XLSX. Убедитесь, что лаборатория получает заявку и вложение, а клиент — подтверждение. Проверьте «Спам». До этого реальная доставка писем не считается проверенной.

## 6. Подключить админ-панель

Настройте действующий HTTPS. В закрытых Environment-переменных Node.js задайте PUBLIC_ORIGIN=https://sael.kb.kg для вашего тестового домена (для основного домена затем замените на https://sael.kg). Укажите только схему и домен, без пути и завершающего слеша.

Через Run script запустите admin:setup, прочитайте CMS_SETUP_TOKEN из .env рядом с server.js, затем Restart App и откройте /admin/. Создайте собственный логин и пароль. Если Run script недоступен, задайте случайный код от 32 символов как CMS_SETUP_TOKEN в Environment, затем Restart App. После создания администратора уберите код и включите TOTP в «Учётная запись».

Папка data/ создаётся вне public/; процессу Node.js нужны права записи. Резервируйте её вместе с media/. Новая загрузка кода не должна удалять data/. Подробности — ADMIN_GUIDE.md. На хостинге проверьте, что запросы /api/ и /uploads/ передаются Node.js: если медиатека загружается, а картинки /uploads/... возвращают 404, попросите провайдера настроить передачу этих запросов приложению.

## 7. Проверка перед переключением домена

- Открываются главная, О компании и все шесть страниц услуг; изображения и сертификаты загружаются.
- На телефоне меню белое, форма и таблица читаются; FAQ закрывает предыдущий вопрос.
- Прайс скрыт до выбора направления; показывается выбранная категория; RU/KG/EN переключаются.
- Телефон, почта, видео и LIMS работают. Тестовый поддомен использует ссылку https://sael.kg/cb.
- Заявка доставляется на sael.karabalta@saelglobal.com; клиент получает подтверждение.
- Через браузер недоступны /.env, /server.js, /package.json и служебные файлы; public — единственный публичный корень.
- Проверены SSL, HTTP→HTTPS, заголовки и сжатие. Выполнены Lighthouse/PageSpeed на хостинге.
- Провайдер подтвердил маршрутизацию /cb и /cb/pricelist.pdf к существующему приложению.

Запуск нового Node-приложения в корне sael.kg без отдельного правила для /cb сломает кабинет: данный server.js кабинет не обслуживает. Не переносите вслепую старую папку cb внутрь public; провайдер должен сохранить прежний обработчик кабинета и его защиту.

## 8. Публикация и возврат

После выполнения RELEASE_CHECK.md переключите основной домен на согласованную конфигурацию. Снимите запрет индексации с рабочего домена. Настройте SEO-редиректы, проверьте старые адреса, в особенности кабинет и прайс, повторите тест формы и проверьте журнал ошибок Plesk. Тестовый поддомен оставьте закрытым от индексации.

Старую папку и резервную копию не удаляйте до завершения проверки. При проблеме восстановите прежний Document Root/обработчик и конфигурацию из копии. После изменения server.js, зависимостей или переменных нажимайте Restart App. После изменения текста в браузерном JS достаточно загрузить файл и обновить страницу.

## Если возникают ошибки

| Симптом | Что проверить |
|---|---|
| Нет Node.js | Доступность Toolkit и тарифа у Hosting.kg |
| 502 / приложение не запускается | Версия Node.js, Startup File=server.js, NPM Install, журнал Plesk |
| Форма 404 | Node.js не включён или /api/quote-request не передаётся приложению |
| Форма 503 | Почтовая конфигурация или ресурс лимитера; смотреть журнал |
| Форма 502 | SMTP/TLS, пароль, разрешённый отправитель, исходящие порты |
| 429 у разных посетителей | Достоверный X-Real-IP и согласованное TRUST_PROXY_IPS |
| Файл блокируется | Разрешённый тип, до 10 МБ; лимит прокси ≥ 12 МБ |
| Новые тексты не видны | Перезагрузка без кеша; новый маршрут server.js требует Restart App |

Источники: [инструкция Plesk](https://docs.plesk.com/en-US/obsidian/administrator-guide/website-management/nodejs-support.76652/), [тарифы Hosting.kg](https://client.hosting.kg/index.php?rp=/store/shared-hosting). Поддержка Node.js в общих тарифах Hosting.kg явно не указана; подтвердите её для вашей подписки.
