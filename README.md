# Сайт SAEL

Версия 2.1 включает помощника с базой знаний и передачей диалога сотруднику. Управление: /admin/ → «ИИ-помощник» и «Диалоги». Подключение ключа, обучение, рабочие часы и почта описаны в ASSISTANT_GUIDE.md. Для генеративных ответов нужен закрытый OPENAI_API_KEY; без него доступны сведения из базы знаний и запрос специалиста.

Адаптивный сайт с RU/KG/EN, защищённой админ-панелью, страницами компании и услуг, онлайн-прайсом из 105 позиций, сертификатами, партнёрами, видео и формой КП с прикреплением ТЗ.

## Запуск в VS Code

Установите поддерживаемую LTS-версию Node.js (рекомендуется 24). Откройте эту папку в VS Code и выполните в терминале:

    npm ci
    npm start

Откройте http://localhost:8020. После изменения server.js или зависимостей остановите сервер Ctrl+C и снова выполните npm start. Для автоматического перезапуска при разработке: npm run dev.

Без SMTP сайт открывается, но форма показывает ошибку отправки. Live Server и открытие index.html как файла не запускают обработчик формы.

## Перенос

Используйте новый sael-site-cms-ai-plesk.zip и DEPLOY_PLESK.md. В архиве публичные файлы находятся в public/, а server.js, cms-server.js, cms-seed.json, package.json и настройки — уровнем выше. Не переносите node_modules с Windows: зависимости устанавливаются на сервере. Сервер поддерживает исходную структуру и public/. Точка запуска — server.js. Браузерный app.js не является точкой запуска Node.js. После обновления обязательно перезапустите приложение. Сохраняйте существующие .env и data/.

## Почта и вложения

Скопируйте .env.example в .env рядом с server.js либо используйте закрытые переменные Plesk. Заполните SMTP_HOST, SMTP_PORT, SMTP_SECURE, SMTP_USER, SMTP_PASS и SAEL_FROM по данным администратора почты. SAEL_QUOTE_TO уже указан: sael.karabalta@saelglobal.com. Отправитель SAEL_FROM должен быть разрешён SMTP-сервером.

Принимается один PDF, XLS/XLSX, DOC/DOCX или ZIP до 10 МБ. Проверяются обязательные поля, согласие, расширение, MIME и сигнатура вложения. Файл передаётся по SMTP и не сохраняется в публичной папке. После уведомления лаборатории сервер пытается отправить подтверждение клиенту. Архива заявок в базе данных пока нет.

Есть скрытое поле от ботов и ограничение 5 попыток за 15 минут с одного IP. Счётчики — в памяти одного процесса. TRUST_PROXY_IPS заполняйте только после подтверждения провайдером, что прокси заменяет X-Real-IP достоверным адресом посетителя. Иначе пользователи могут делить один лимит. Для нескольких процессов нужны общие лимиты. CAPTCHA и антивирус не подключены.

## Редактирование

- index.html, about.html, service.html — структура.
- app.js — интерфейс RU/KG/EN, строки прайса, контакты и взаимодействия.
- price-translations.js — переводы пояснений прайса.
- service-content.js, about-content.js — подробные тексты RU/KG/EN.
- styles.css, service-details.css, about.css — оформление.
- assets/ — изображения, сертификаты и логотипы.
- server.js — форма и раздача разрешённых файлов.

Обычные изменения делайте в админ-панели /admin/. Первую учётную запись создайте по ADMIN_GUIDE.md; общего пароля по умолчанию нет. Для локального запуска выполните npm run admin:setup, возьмите код CMS_SETUP_TOKEN из закрытого .env и перезапустите npm start. На хостинге сначала настройте HTTPS и PUBLIC_ORIGIN. Содержимое, пользователи, медиатека, журнал и 10 последних версий сохраняются в data/ вне публичной папки. При первом запросе начальный контент импортируется из cms-seed.json; после этого редактирование исходных текстовых JS не меняет сохранённую CMS-базу.

Страницы, разделы, блоки, меню, услуги, прайс, FAQ, документы, партнёры, оборудование, изображения и контактные данные редактируются в интерфейсе. Есть RU/KG/EN, черновики, порядок, удаление и восстановление версии, медиатека и TOTP. Текущая роль — администратор с полным доступом; отдельных ролей редактора/переводчика пока нет. Не помещайте пароли и внутренние документы в public/ или assets/.
